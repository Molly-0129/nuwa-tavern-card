# 彩石与众妙 · 状态栏

原「众妙」的分层设计可保留：一组规则负责隐藏或展示变量更新，另一组处理状态栏标记。女娲 1.48 附件里有生成状态栏的提示词，随附的实际正则只处理预设思绪。这里修订的是生成方案，不代表已审过某张已成卡的界面。

## 众妙的修改

- 原清理表达式遇到更新块中包含 JSON 字符串的 > 时可能漏掉；原完整表达式使用贪婪捕获，多个同名块之间的正文可能一起被匹配。改为逐块配对并分开处理消息末尾尚未闭合的更新。
- 明确作用域。仅对 AI 输出启用。提示词清理仅勾「仅格式提示词」，显示规则仅勾「仅格式显示」，原消息中的协议块保留给 MVU 解析。默认把完整 JSON Patch 解析为可折叠的「本轮变化」。内容逐项显示变量名称、数值增减或新值，例如「晏无咎 · 好感度 +1」或「剧情 · 阶段 → 猎心」。增加与减少采用不同颜色，布尔值使用「是／否」。空更新显示「本轮无变量变化」。旧协议只显示完成提示。流式未闭合时显示「正在更新变量…」，闭合后切换为完整态。需要换行时写入真实换行，JSON 序列化时统一转义，避免在聊天里出现字面 `\n`。展示调试原文时，使用可信组件的 textContent，并由用户决定是否提供调试视图。
- 同一个状态栏标记用于提示词隐藏和界面替换，分别设置各自的作用域。开场白与每个需要显示面板的备选开场末尾放一次标记。正文生成规则也只要求一次。读该消息楼层的 stat_data，切换旧消息、重掷、编辑和切换开局时检查对应状态。变量缺失时显示「未初始化」或「—」，保留真实的 0、false 和空状态。
- 轻量方案用经过目标版本验证的酒馆助手宏，限制在合法数值、布尔或白名单枚举等已约束的值。格式化宏与原值宏可能返回不同文本，先验证宏作用域、返回值和渲染顺序。自由文本字段用受支持的酒馆助手界面组件读取，赋给节点的 textContent。状态栏做只读展示，剧情更新走 MVU。优先系统字体、折叠详情、主题可读对比、窄屏可换行及无动画默认。
- 已有 MVU 预设的更新规则先去重。上游协议标签与目标不一致时调整匹配器并复测。若协议使用字面标签作数据，需要针对该版本的协议处理转义。

## 生成与接入

可从 [EJS 面板样板](../assets/mvu-panel.ejs) 改写面板。样板使用上游教程中的 render 钩子与当前楼层读取接口。示例字段为 剧情.阶段、剧情.线索数、剧情.盟约生效，接入时换成卡片真实字段。样板处理标量与旧版值/说明结构，只有目标类型确实采用该结构时才保留数组判断。默认全部转义后再渲染。

准备面板替换文本后，用 Node.js 动态导入 scripts/mvu-status.mjs，调用 buildMvuRegex({ panel })。panel 为空时只生成变量更新显示/清理规则。panel 是作者生成的显示内容，使用真实、已约束的变量路径。若已验证目标 SillyTavern 的角色正则封装，把数组中的记录追加到 data.extensions.regex_scripts 并保留无关既有规则。也可按用户需求单独导出正则记录用于导入。升级旧卡时，用整组新版显示规则替换旧的更新显示规则，并按生成顺序排列。先转义 JSON Patch 正文，再由内嵌酒馆助手界面用 JSON.parse 解析、textContent 填入条目，最后处理旧协议和流式状态。界面依赖酒馆助手，使用 HTML 代码围栏承载。scripts/mvu-update-view.mjs 提供变化文本和界面渲染逻辑。解析失败时提示核对 MVU 变量面板。生成后验证界面能执行、详情能展开、数值为 0 或 false 时能准确显示。仅当用户要求隐藏时传入 decorateUpdates: false。导出后实际运行显示与提示词两种替换，至少检查跨行 JSON Patch、同条消息的两个更新块、尾部未闭合块以及状态栏标记。相关规则的命名或状态栏标记已存在时，就地替换对应规则、保留原 ID。当前端格式依赖酒馆助手渲染时，使用该版本文档指定的围栏或 iframe 入口，并实机验证。

彩石的纯文本方案可沿用「文本模板 → 展示样式 → 捕获正则」，使用明确边界和字段顺序。对可由模型或玩家生成的文本，通过受支持的文本渲染或转义流程展示。静态 HTML/CSS 使用作用域类名，避免干扰酒馆界面其他区域。
